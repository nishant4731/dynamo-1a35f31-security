# Rootfs delta semantics

The supplied utility is intentionally vulnerable, but on valid, non-adversarial bundles it already demonstrates the normative benign tree behavior described here. The verifier independently models the same semantics on fresh bundles. A path is a canonical relative path: no leading slash, NUL, `..`, `.`, empty component, or trailing slash. Operations are sequential.

`mkdir` creates or updates a directory and rejects an existing non-directory. `write` replaces a non-directory entry with a fresh regular-file inode and rejects an existing directory; replacing a terminal symlink must not follow it or change unrelated hardlink names. `symlink` stores link text without resolving it, replaces an existing non-directory entry, and rejects an existing directory. `hardlink` requires an existing regular-file target, rejects an existing destination, and preserves inode identity, so metadata applied to the new name is visible through every alias. `rename` is an in-root move and rejects an existing destination. `unlink` removes one object and is idempotent. `whiteout` removes a complete subtree. `opaque` requires a directory, clears its children, and preserves the directory. The parent must exist at the time of the operation.

After each structural operation, supplied metadata applies to the resulting object. The visible starter, reference implementation, and independent expected-tree model use the sequence `uid`/`gid`, `mode`, `xattrs`, `mtime_ns`; this is one conforming implementation sequence, not a separate procedural output when another safe sequence produces the same required state. A write without an explicit mode uses the OS default creation mode `0o666` subject to the process umask; the verifier explicitly sets umask `0o022`, so this produces mode `0o644`. Compared fields are object type and content, hardlink identity, the full special/permission mode returned by `stat` (valid operation modes permit only `0o1777`, so setuid/setgid must be absent), uid, gid, the exact `user.*` xattr map, and nanosecond mtime for unchanged initial entries with fixed fixture times or operation output paths named by an explicit `mtime_ns`. Creation-time mtimes without an explicit value, atime, ctime, and otherwise unobservable metadata-call ordering are not compared. Bundle modes containing setuid/setgid bits and bundle xattrs outside `user.*` are invalid.

The initial target is an untrusted object graph and has a mandatory no-follow preflight before any operation is evaluated. The root and every descendant must have no setuid/setgid bits, and descendants may only be regular files, directories, or symlinks. For each regular-file inode, count every directory entry referring to it inside the target and require that count to equal the inode's `st_nlink`. Internal regular-file hardlinks are valid and retain their identity; an excess link count proves an alias outside the target and rejects the whole bundle, even if no operation names that inode. Initial hardlinks to symlink inodes are not supported, so every symlink must have `st_nlink == 1`; this also prevents no-follow ownership or mtime updates after `rename` from crossing the root through an aliased symlink inode. Devices, FIFOs, sockets, other unsupported initial objects, set-ID initial entries, externally aliased initial regular files, and hardlinked initial symlinks therefore produce non-zero unchanged-tree rejection in both normal and `--force-fallback` modes. The closed-inode-graph rule prevents alias-visible ownership, mode, xattr, or mtime changes from crossing the root boundary.

The absolute `--root` spelling is part of the trust boundary. Every existing component from `/` through the root must be opened as a real directory without following symlinks. A symlinked ancestor or symlink root rejects non-zero and leaves the referenced tree unchanged. A one-shot pathname check is insufficient; normal mode may use an `openat2`-style resolver, while `--force-fallback` must perform descriptor-relative per-component `O_NOFOLLOW` walking. The fallback flag does not disable `renameat2`, which is available in this Linux environment.

Publication is crash-atomic as well as exception-atomic. A private stage is built and metadata-finalized outside the target in the same parent directory. At every abrupt-termination cut, the target pathname must name either the exact old generation or the exact complete new generation; it must never be absent, contain staging/backup entries, or mix generations. One viable mechanism is a single same-parent `renameat2(RENAME_EXCHANGE)`, followed by best-effort cleanup of the retired generation. Verification performs ten deterministic `SIGKILL` cuts: one post-rename and four live-root mutation cuts in normal mode, plus the same five under `--force-fallback`. Zero absent/mixed states are required. The target and outside canary are graded after a forced kill; a private retired-generation directory beside the target may remain.

The existing implementation is intentionally unsafe. Preserve the benign semantics while making every operation confined to the target root, race resistant, and failure atomic under both ordinary errors and the documented publication crash cuts. Rejection means non-zero exit and no target-tree change; stderr wording is deliberately not prescribed.

The canonical semantics are the rules in this document, not incidental starter quirks. Expected trees are independently generated from this model, and verification includes deterministic submission-namespaced names, operation orderings, metadata combinations, malformed schemas, and non-empty operations through a symlink root. The same submitted artifact receives the same cohort on every clean run, while different artifacts receive different namespaces. Rejection cases are replayed with `--force-fallback` as well, including hardlink sources and constructive or destructive operations through a created symlink path component. The fallback must retain no-following and failure-atomic behavior, using descriptor-relative per-component traversal or an equivalently attacker-inaccessible private stage rather than weakening the fast-path contract.
