# Rootfs delta semantics

The visible sample is normative for the benign behavior of the supplied utility. The verifier uses the same semantics on fresh bundles. A path is a canonical relative path: no leading slash, NUL, `..`, `.`, empty component, or trailing slash. Operations are sequential.

`mkdir` creates or updates a directory and rejects an existing non-directory. `write` replaces a non-directory entry with a fresh regular-file inode and rejects an existing directory; replacing a terminal symlink must not follow it or change unrelated hardlink names. `symlink` stores link text without resolving it, replaces an existing non-directory entry, and rejects an existing directory. `hardlink` requires an existing regular-file target, rejects an existing destination, and preserves inode identity, so metadata applied to the new name is visible through every alias. `rename` is an in-root move and rejects an existing destination. `unlink` removes one object and is idempotent. `whiteout` removes a complete subtree. `opaque` requires a directory, clears its children, and preserves the directory. The parent must exist at the time of the operation.

After each structural operation, metadata is applied in this exact order: `uid`/`gid`, `mode`, `xattrs`, `mtime_ns`. A write without an explicit mode uses the OS default creation mode `0o666` subject to the process umask; the verifier uses umask `0o022`, so this produces mode `0o644`. Compared fields are permission and sticky-bit mode, uid, gid, nanosecond mtime, and all declared `user.*` xattrs. Device nodes, FIFOs, sockets, setuid/setgid modes, and non-`user.*` xattrs are invalid.

The existing implementation is intentionally unsafe. Preserve the benign semantics while making every operation confined to the target root, race resistant, and failure atomic. Rejection means non-zero exit and no target-tree change; stderr wording is deliberately not prescribed.

The canonical semantics are the rules in this document, not incidental starter quirks. Expected trees are independently generated from this model, and verification includes deterministic submission-namespaced names, operation orderings, metadata combinations, malformed schemas, and non-empty operations through a symlink root. The same submitted artifact receives the same cohort on every clean run, while different artifacts receive different namespaces. Rejection cases are replayed with `--force-fallback` as well, including a created symlink used as a non-empty path component. The fallback must retain no-following and failure-atomic behavior, using descriptor-relative per-component traversal or an equivalently attacker-inaccessible private stage rather than weakening the fast-path contract.
